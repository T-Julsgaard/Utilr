02 what it does

the last thing you copied is never the only one. find it by a few letters.

>find as you type

A few letters find every clip that has them, matches marked. Newest first, the time on the right.

>pasted where you were

Enter puts the clip back in the window you came from and pastes it (Windows). Shift+enter only copies.

>only in memory

The history is never written to disk. Quit utilr or restart the computer and it starts a clean day.

>private clips stay out

What password managers mark as private is never kept, on Windows, macOS and Linux. Pause recording any time.

>text only

Images and files are left alone. Copy the same thing again and it moves to the top instead of showing twice.

>costs nothing

The popup is made the first time you open it and closed again after five minutes unused. Reading the clipboard takes about 0.1 ms.

04 the details

  • limits

    At most 200 clips and 4 million characters in all; the oldest go first. A single clip over a million characters isn't kept.

  • private, precisely

    On Windows the formats Windows' own history respects (ExcludeClipboardContentFromMonitorProcessing, CanIncludeInClipboardHistory = 0), on macOS org.nspasteboard.ConcealedType, on Linux KDE's password manager hint. While paused, nothing is kept.

  • how it pastes

    The popup steps aside so Windows gives focus back to the window you were in, then ctrl+v is sent with the script host every Windows has. About 60 ms.

  • settings

    Paste on pick, where it appears (pointer or center), its key, pause. ctrl+, in the popup.
